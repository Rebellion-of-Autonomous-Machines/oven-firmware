# Ethernet / Modbus TCP: модуль двери скоростной печи

## Параметры

- Контроллер Ethernet: `W5500`
- SPI: `SCK GPIO18`, `MISO GPIO19`, `MOSI GPIO23`
- CS: `GPIO5`
- Modbus TCP: порт `502`, Unit ID `1`
- MAC: `02:A0:C9:00:00:63`
- Адрес по умолчанию: статический `192.168.1.52`
- Маска: `255.255.255.0`
- Шлюз и DNS: `192.168.1.1`

Поддерживаются функции Modbus `0x03` (Holding Registers), `0x04` (Input Registers), `0x06` (Write Single Register) и `0x10` (Write Multiple Registers). Прямое подключение RS-485 больше не используется.

## Настройка Ethernet

Веб-интерфейс доступен через точку доступа Wi-Fi `oven`, пароль `clickclick`. Обычно адрес интерфейса: `http://192.168.4.1/`.

В разделе **Ethernet / Modbus TCP** можно выбрать:

- статический IP с ручным вводом IP-адреса, маски, шлюза и DNS;
- DHCP с автоматическим получением адреса.

Настройки сохраняются в NVS и восстанавливаются после перезапуска. Они применяются сразу после сохранения. Во время движения двери изменение сетевых параметров блокируется. В интерфейсе отображаются состояние W5500, текущий Ethernet IP и подключённый Modbus TCP-клиент.

В документации используются адреса вида `40001` и `30001`. В библиотеках, принимающих нулевые смещения, адресу `40001` соответствует offset `0`, а адресу `30001` также соответствует offset `0` для Input Registers.

## Holding Registers

| Адрес | Offset | Доступ | Название | Значение |
|---|---:|---|---|---|
| `40001` | `0` | RW | `Stat_Mode` | Состояние автоматики |
| `40002` | `1` | RO | `Stat_Error` | Код ошибки |
| `40003` | `2` | RW | `Man_Control_C` | Код команды `C` |
| `40004` | `3` | RW | `Man_Control_X` | Аргумент `X` |
| `40005` | `4` | RW | `Man_Control_Y` | Аргумент `Y` |
| `40006` | `5` | RW | `Man_Control_Z` | Аргумент `Z` |
| `40007` | `6` | RW | `Command` | Совместимая числовая команда двери |
| `40008` | `7` | RO | `Command_Result` | Результат последней команды |
| `40009` | `8` | RO | `Direction` | Текущее направление мотора |
| `40010` | `9` | RO | `Status_Bits` | Расширенные флаги состояния |
| `40011` | `10` | RO | `DI_Bits` | Состояния DI5/DI6 |

### Stat_Mode (`40001`)

- `1` — начальное состояние, готовность к работе.
- `11` — выполняется сценарий движения двери.
- `19` — сценарий завершён.
- `20` — ручное управление через `Man_Control`.
- `30` — экстренная остановка.
- `99` — ошибка.

Запись значения `1..20` снимает ошибку, если условие ошибки устранено. Для выполнения `Man_Control` нужно установить `Stat_Mode=20`. Запись `30` немедленно останавливает двигатель и переводит положение двери в неизвестное.

Запись `Stat_Mode=11` из состояния `1` запускает безопасный сценарий открытия. Из любого другого состояния такая запись возвращает ошибку `102`. После завершения движения состояние становится `19`.

### Stat_Error (`40002`)

- `0` — ошибок нет.
- `100` — команда `Man_Control` без режима `20`.
- `101` — команда во время движения или невозможного текущего цикла.
- `102` — неизвестная команда или недопустимое состояние.
- `103` — удалённое управление заблокировано ключом.
- `105` — прямое управление реле запрещено.

При ошибке `Stat_Mode` становится `99`.

### Man_Control (`40003-40006`)

Четыре регистра записываются одновременно в формате `C X Y Z`. Команда обрабатывается только при `Stat_Mode=20`, после обработки регистры автоматически очищаются.

| C | X | Y | Z | Действие |
|---:|---:|---:|---:|---|
| `1` | `0` | `0` | `0` | Безопасно открыть дверь |
| `2` | `0` | `0` | `0` | Безопасно закрыть дверь |
| `5` | любое | любое | любое | Всегда отклоняется: `Stat_Error=105`, `Command_Result=6` |

Протокол не предоставляет прямого управления отдельными реле. Управление двигателем выполняется только командами открытия и закрытия, чтобы исключить недопустимые сочетания выходов.

### Дополнительная команда (`40007`)

- `0` — нет команды.
- `1` — открыть дверь.
- `2` — закрыть дверь.

Регистр сохранён для совместимости с предыдущей версией протокола. После обработки сбрасывается в `0`.

### Command_Result (`40008`)

- `0` — `OK`.
- `1` — неизвестная команда.
- `2` — устройство занято.
- `3` — требуется `Stat_Mode=20`.
- `4` — неверный аргумент.
- `5` — удалённое управление заблокировано.
- `6` — прямое управление реле запрещено.

### Direction (`40009`)

- `0` — стоп.
- `1` — открытие.
- `2` — закрытие.

### Status_Bits (`40010`)

- bit0 — дверь движется.
- bit1 — виртуальный концевик «открыта».
- bit2 — виртуальный концевик «закрыта».
- bit3 — команды веба/Modbus разрешены.
- bit4 — ключ в ручном положении «открыть» (`DI5=1`, `DI6=1`).
- bit5 — ключ в ручном положении «закрыть» (`DI5=0`, `DI6=1`).
- bit6 — недопустимое состояние входов или ошибка их чтения.
- bit7 — ручная команда ключа ожидает возврата в `Автомат`.

### DI_Bits (`40011`)

- bit0 — DI5.
- bit1 — DI6.
- bit2 — данные входного расширителя получены.

## Input Registers

| Адрес | Offset | Название | Значение |
|---|---:|---|---|
| `30001` | `0` | `Tlm_TimeAll` | Накопленное время работы, часы |
| `30002` | `1` | `Tlm_TimeHeat` | Пока равно `Tlm_TimeAll`, часы |
| `30021` | `20` | `Tlm_end_open` | Виртуальный концевик «открыта», `0/1` |
| `30022` | `21` | `Tlm_end_closed` | Виртуальный концевик «закрыта», `0/1` |

Время накапливается в секундах и сохраняется в NVS каждые 10 минут, чтобы снизить износ flash. Наружу передаётся целое количество часов, максимум `65535`. `Tlm_TimeHeat` временно равен `Tlm_TimeAll`.

## Управление дверью

- При включении выполняется обязательное закрытие в течение 6 секунд.
- После достижения положения повторная команда в том же направлении считается успешно выполненной без запуска двигателя.
- Во время движения новые команды не принимаются.
- В положении ключа `DI5=1, DI6=0` разрешено удалённое управление.
- Ручная команда ключа запускается после выбора направления и возврата ключа в автоматическое положение.

## Python-тестер

Файл: `tools/modbus_tcp_door_tester.py`

Установка:

```bash
pip install pymodbus
```

Запуск:

```bash
python tools/modbus_tcp_door_tester.py
```

В тестере указываются IP-адрес W5500, TCP-порт и Unit ID. Он записывает `Stat_Mode=20` и `CXYZ` одной командой `Write Multiple Registers`, читает Holding Registers, телеметрию времени и виртуальные крайние положения двери.
